# Changelog

What changed in pkm. The next version's changes are collected here; each released version's notes, including manual steps for existing vaults, are on its GitHub release, linked below.

Version numbers: **major** when a command, option, output format, note name, link syntax, frontmatter field or folder is renamed or removed, since agentic-pkms skills, editors and existing notes depend on them; **minor** for new commands, options and templates; **patch** for fixes. Before 1.0, a minor version may also need manual changes; its notes list them under "Manual steps". Each release is a git tag (`v0.1.0`), and `pkm version` shows which one is installed.

## 0.1.0 (unreleased)

- **pkm is a standalone command**, installed once per machine as `bin/pkm`, with its modules in `lib/pkm/` and its default templates in `share/pkm/`. It works on any plain Markdown vault with no agent and no plugin. It is not an agd kit.
- **Finding the vault**: the folder that holds `.pkm/`, from the current folder up; `--vault <folder>`, `PKM_VAULT`, `vault=` and named vaults (`-V <name>`, with `vault_<name>=` lines) in the user config. `pkm vault` and `pkm vaults` show them.
- **Settings** come from one list (`docs/settings.md`), in the vault's `.pkm/config` or the user's `~/.config/pkm/config`. `pkm config` shows each value and its source, and `pkm doctor` reports a setting pkm doesn't know.
- **`.pkmignore`** hides files and folders from every command, in gitignore syntax. `.gitignore` is not followed.
- **Templates** come from three places: the vault's `templates/` folder, `~/.config/pkm/templates/`, then the defaults. `pkm templates` lists them, and `pkm templates eject <type>` copies a default to change it. A type with no template is made from the note template.
- **Day pages**: `day` makes today's page in `daybook/<year>/<month>/`, and `add` writes an entry at the end of its Log, printed as `path:line`. A shared vault writes `<date>-<writer>.md`.
- **Tasks**: a task is any `- [ ]` line outside code, in any note (boxes in list notes and struck lines are not tasks). `tasks` lists them in groups (overdue, due soon, waiting, the rest); `done` marks one and moves an interval routine on; `todo` writes under the day page's Tasks section; `upcoming` lists what is due and the birthdays and target dates. Relative dates such as `friday` or `+3d` are read against the day page they are on.
- **Notes from templates**: `new` names each note by its type's rules and puts it in the type's folder.
- **Finding**: `find` (words, any order, smart case), `backlinks` (through a note's name, slug or alias), and `path`, `list`, `tags`, which print paths relative to the vault and `path:line: text` lines that editors can open.
- **Links** resolve by file name, by the slug of the link's text, or by an alias in the note's frontmatter, anywhere in the vault. `check` reports broken links (and says when the file is in `.pkmignore`), duplicate names, alias clashes, secrets and merge conflict markers; a link that works only by slug or alias is a notice. `links --external` lists the web addresses with their places, and `check --urls` (opt-in, with curl) reports those that give no answer or a 404 or 410.
- **Reading and posting**: `get` prints a note or one section between headers, with the note's own line numbers. `post` copies lines of a day page into a note's section, verbatim, with the page as their source (`([[2026-11-10]])`), and `strike` strikes a line through when it is no longer true and links today's page. Both refuse what would break the notes (a heading in a range, an open task, a day or close target).
- **Evidence**: `evidence [--verify]` checks that each list item of a note's `## Now` section, a close page, or stdin links its source: a day page, a source note, a `path:line` or a web address. `--verify` checks that the links resolve and the lines exist.
- **Lists**: `list --quiet <days>` lists the notes that no recent day page links.
- **Cycles and the close**: the week is built in, and your own cycles are set in `.pkm/config` (`cycle_<name>=2w from 2026-11-02`, `cycle_<name>=1m from 15`). `cycle` prints the period holding a date. Routines can say `(every <cycle>)`: an undated one is due on the last day of the current period, and `done` moves it on by period. `since` shows what happened since a date, a number of days, or a cycle, with `--about` and `since --seen` for the next run. `close` lists what the period leaves open and what comes due, and `new close` writes the close page.
- **Moving and renaming**: `rename <old> <new>` renames a note and rewrites every link to it, outside code, keeping the text readers see; the old name becomes an alias unless `--no-alias`, and `--dry-run` lists the changes. `mv <note> <folder>` moves a note and keeps its links. Both record the move in `.pkm/moves.tsv`, and a failure rolls every file back.
- **Cache**: `index` keeps `names`, `list`, `path` and `check` fast on a large vault, in `.pkm/cache`. It is a speed-up only: deleting it never changes an answer, and a changed file is read again by its size and mtime. `names [--type]` lists the names; `list` shows path, type and title, then the fields asked for.
- **Output contract**: `docs/contract.md` describes every command and its output. Listings take `--json` (JSON Lines with `path`, `line` and `text`), `--abs` and `--limit`, and exit 1 when they have no results. `pkm help --all` lists the commands.
- **Tools and versions**: pkm expects ripgrep and jq, and git for a history; `pkm doctor` shows what is installed. `pkm version --require <x.y>` tells a caller whether the release is new enough.
- **Install**: `make install PREFIX=<folder>` (default `$HOME/.local`) copies pkm to `<folder>/lib/pkm-<version>/` and links `<folder>/bin/pkm`; `make uninstall` removes what it made. `sh install.sh --prefix <folder>` does the same from an unpacked tarball or a clone, with no download, and then runs `pkm doctor`.
- **Tarball**: `make dist` writes `dist/pkm-<version>.tar.gz` and its `.sha256`. The release workflow builds it on every run and attaches it to the GitHub release. `scripts/formula.sh` fills the Homebrew formula in `packaging/pkm.rb` from the tarball.
- **Extensions**: an unknown command `pkm <name>` runs `pkm-<name>` from PATH, with the same arguments, the vault in `PKM_VAULT`, and its exit status. Built-in commands always win, and extensions are never read from a vault. `pkm help --all` lists the extensions found.
- **Later task kinds**: `(start <date>)` hides a task until its day (`upcoming` lists it on that day, and `tasks --all` marks it); `(someday)` keeps a task out of the weekly views, and shows it in `tasks someday` and the quarterly close. A routine belongs in a note: `check` flags one on a day page, and flags the old rules (`day`, `monday, thursday`, `month on 15`), which `todo --every` no longer takes. `todo --every` takes `<N>d`, `<N>w`, `<N>m`, `<N>y` or a cycle name.
- **Routines note**: `todo --every` writes the routine to the note named `routines`, found by name in any folder, or created from the note template as `notes/routines.md` (titled Routines) when there is none. It goes at the note's end, so `check` stays clean; a plain `todo` still goes on today's page.
- **Since seen**: `since --seen` stores the date and the time (`since=YYYY-MM-DD HH:MM`; the date-only form still reads), so `since last` leaves out the entries of the seen day timed at or before the seen time. `get --lines` clamps an end past the file. `PKM_NOW` is documented in the contract.
- **Recall add**: `pkm recall add <note> <question> [--answer <text>]...` writes a question at the end of the note's `## Questions` section (made when missing), due tomorrow, with each answer indented below. It refuses a day or close page and a question the note already has. The study pack writes accepted questions this way.
- **Recall**: a question ends with `(recall YYYY-MM-DD <N>d)`. `recall` lists the ones due today or earlier, oldest first, and `recall <path:line> yes|no` moves one up the ladder of 1, 3, 7, 14, 30, 60 and 120 days, or back to 1 day. `check` flags a malformed mark and a mark in a task box. A `course` template (`## Modules`, `## Questions`) is added.
- **Editors**: `share/pkm/editors/vscode/tasks.json` runs `pkm day`, `add`, `find`, `tasks` and `check`, and reads the `path:line: text` lines as problems.
- **Docs**: the README is a one-page start with the command table; `docs/format.md` specifies the file format (Format 1); `docs/editors.md` has Neovim, VS Code and Obsidian recipes; `AGENTS.md` holds the repo rules, portability, line endings and releases.
