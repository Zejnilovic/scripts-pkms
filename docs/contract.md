# The output contract

This file is the one description of pkm's interface: its commands, what they print, their exit codes and their options. Scripts, editors and agents call pkm, so these hold across releases; a change to any of them is a major version (see [CHANGELOG.md](../CHANGELOG.md)). A test fails when a command or an output field is missing here.

## Commands

`pkm help --all` prints one line per command, `name<TAB>group<TAB>summary`. Each command below is in that list.

| Command | Group | Does | Listing (`--json`, `--abs`, `--limit`) |
|---|---|---|---|
| `day` | Capture | the day's page, created when missing; prints its path | no |
| `add` | Capture | an entry at the end of the day's Log, printed as path:line; `--file` copies a file into `files/` and links it | no |
| `todo` | Tasks | a task for today, under its Tasks section; a routine (`--every`) goes to the note named routines, created when missing, or with `--in <note>` to that note's Routines section; prints path:line | no |
| `done` | Tasks | marks the one open task that matches as done, or as dropped with --drop; moves a routine on, or to the day --next gives | no |
| `moved` | Tasks | strikes a task or an event whose date changed and writes it again with the new date; prints path:line: text | no |
| `tasks` | Tasks | the open tasks of every note, in groups: overdue, due soon, waiting, the rest | yes, `path:line: text` lines in groups; `--json` adds `group`, `due`, `state` |
| `upcoming` | Review | birthdays, due tasks, events, dates and the start dates of hidden tasks in the next days; `--ics` writes the events as a calendar file | no; `--json` gives `date`, `kind`, `time` and `end` |
| `new` | Notes | a note of a type, made from its template | no |
| `backlinks` | Find | every line that links a note, by name, slug or alias, and the lines under a `###` heading that links it | yes, `path:line: text` lines |

| `check` | Check | broken links, duplicate names, alias clashes, secrets, merge conflicts and notices | yes, problems and notices |

| `cycle` | Review | the period of a cycle holding a date (today by default): name, first and last day; `close` marks the close cycle | no; `--json` gives `name`, `first`, `last` and `close` |
| `since` | Review | what happened since a date, a number of days, or a cycle: notes, log, tasks, marked entries and names; `--about NAME` | yes, `path:line: text` lines in sections; `--json` gives a `kind` per line |
| `recall` | Review | the recall questions due today or earlier, oldest first; `recall <path:line> yes\|no` moves one on the ladder; `recall add <note> <question>` writes one | yes, `path:line: text` lines |
| `close` | Review | the close of a period: the first line, then tasks, open questions, what is due, marked entries, names, quiet notes and ideas | no; `--json` gives a `kind` per line |

| `get` | Notes | a note or one section of it, between a header and a footer; `--lines` takes a range | no |

| `vault` | Setup | the vault's folder | no |
| `vaults` | Setup | the named vaults of the user config | no; `--json` gives `name`, `path` and `state` |

## Listings

The cache (`index`, in `.pkm/cache` or `PKM_CACHE_DIR`) is a speed-up only: deleting it never changes an answer. `names`, `list`, `path` and `check` read it, and `index` brings it up to date (`--rebuild` starts it again).

`find`, `backlinks`, `tasks`, `check`, `path` and `list` print their results in one of four forms:

- **`path:line: text`** (`find`, `backlinks`, `tasks`): the path from the vault's root, the line number, and the text of the line.
- **Paths** (`path`): one path per line.
- **Table rows** (`list`): `path | field | ...`, with the fields `--show` asks for.
- **Check** (`check`): a `Problems:` and a `Notices:` section, each with `- ` lines. A line with a place is `- path:line: text`; a line without one has no path.

Other commands print what they say in plain text, and take none of these options.

### Options

- **`PKM_NOW=YYYYMMDDHHMMSS`** (environment): fixes the clock: today, the time `add` writes, and the time `since --seen` stores. It is for tests and for backfilling a day; any other value exits `2`.
- **`--abs`**: paths are absolute, from the vault's folder.
- **`--json`**: JSON Lines, one object per record, parsed by `jq` and by Python's `json`. Headers and summaries (such as `Checked 12 notes.`) are not records and are left out. Keys:
  - `path`: the path from the vault's root, or `null` when a record has none (a problem with no place).
  - `line`: the line number, or `null`.
  - `text`: the text of the record, or `null`.
  - `kind`: for `check` only, `problem` or `notice`.
  - `url`: for `links` only, the address, in place of `text`.
  - `fields`: for `list` only, the list of the row's fields after its path.
- **`--vaults [<name>,<name>...]`** (before the command, in place of `-V` and `--vault`): runs `tasks`, `upcoming` or `since` in each named vault (`vault_<name>` in the user config), in the order given, or in the order of the `vaults=` setting when no names are given. A word after `--vaults` that is one of those commands, or an option, is not a list of names. Each vault with records prints `== vault <name>`, then exactly what `pkm -V <name>` prints, paths relative to that vault (`--abs` makes them absolute). A vault with none (exit `1`) is left out. `--json` prints the records of every vault with a `vault` field added, and no headers. Footers go to stderr, as usual. Exit `0` when a vault had records, `1` when none had; `2` (printing nothing) for a name with no vault, a list with an empty name, no names and no `vaults=` setting, another command, `--ics`, or `-V` or `--vault` with it. Nothing is copied or linked between vaults.
- **`--limit n`**: the first `n` records only, default 30 (the `limit` setting). When more follow, a footer `... N more (use --limit)` goes to stderr, never to stdout.

## Order

Every listing is deterministic: the same vault gives the same output, in plain and in `--json`, on every run.

- **`find`, `backlinks`, `path`, `list`**: by path in byte order (`LC_ALL=C`), then by line number. `--limit` takes the first records of that order.
- **`recall`**: by the question's due date, oldest first, then by path and line in byte order.
- **`names`**: by name, then by path. Day and close pages, and files other than notes, are left out unless `--type` names them. `--json` gives `path`, `line` and `text` as `null`, and `fields` as `[name, type, aliases]`.
- **`list`**: by path. Each line is `path<TAB>type<TAB>title`, then the fields named by `--show`. `--json` gives the same columns as `fields`, after the type and title.
- **Later kinds**: a task with `(start D)` is hidden until D: `tasks`, `since`, `close` and the due lines of `upcoming` leave it out, `upcoming` lists it on its start date as `<D> start path:line: text`, and `tasks --all` shows it marked `starts D:`. A `(someday)` task is shown only by `tasks someday` and by the quarterly close (`close --quarter`, or a quarter's first period), and it is left out of the 21-day rule even with a due date. A `(someday)` task with a start date is an ordinary task from that date. A routine on a day page, and an old rule, are `check` problems, and so are the event problems in [format.md](format.md), Events 6. An event is never a task: `tasks` and the close's `== tasks` leave it out, and `upcoming` and the close's `== due` list it.
- **`tasks --for <who>`** keeps the open tasks and the questions that are someone's ([format.md](format.md), Tasks): those with a `(for …)` naming them, and, for a writer of a shared vault, the tasks on their day pages without a `(for …)`. `<who>` is a writer's name, or a note's name, alias or `[[link]]`, resolved as a link is. A question is listed with the tasks of no date. Exit `1` when `<who>` names no writer and no note; `2` when it is missing.
- **`--under <note>`** on `tasks`, `since`, `list` and `backlinks` keeps the records of the note's tree: the note and every note under it by `part_of` ([format.md](format.md); day and close pages and `archive/` are not in a tree), and the lines of day pages that are about one of them: a line that links it, or a line under a `###` heading that links it, until the next heading of level 1, 2 or 3. `list` keeps the notes of the tree. `<note>` is a note's name, slug, alias, `[[link]]` or path. Exit `1` when it names no note; `2` when it is missing.
- **`backlinks <name>`** lists every line that links the note, by name, slug or alias, archive included, and every line under a `###` heading that links it, until the next heading of level 1, 2 or 3, in any file. A name with no note yet gets the lines that write the link as it is written, and the lines under a heading that does. `--since <date>` leaves out the day and close pages dated before it. Exit `1` when no line links the name.
- **`tasks`**: in groups, each group in its own order:
  1. **overdue**: due before today, oldest due date first;
  2. **due soon**: due within `due_soon_days` (7) from today, soonest first;
  3. **waiting**: waiting for more than `waiting_days` (7), longest wait first;
  4. **other**: the rest, by due date (undated last), then by the day page's date (undated pages first), then by path and line.
  `--json` gives each task its `group` (`overdue`, `due_soon`, `waiting_long`, `other`, or `done` for the done view), its `due` date (or `null`) and its `state` (`open`, `done` or `dropped`, or `question` for a question with `--for`).
- **`check`**: its own order, as documented here: the Problems section first, then the Notices section. Within each, problems come in the order the checks run: duplicate names, then links in the order of the vault's files and, within a file, its lines, then alias clashes, then file names that aren't slugs. `--json` keeps the same order.

## Exit codes

- `0`: a match, or a success.
- `1`: nothing matched or nothing found (a listing with no records), or `check` found problems, or `version --require` is too old.
- `2`: a wrong call (including an unknown option, such as `--nope`, which prints one line on stderr), a missing tool (ripgrep for searching, jq for `--json`), or no vault.

Errors go to stderr. Output goes to stdout.

## Renames and moves

- `rename <old> <new>` prints `Renamed <old> to <new>: ...` on success. With `--dry-run` it prints one `path:line: before -> after` line per changed line, and the alias change to the note's frontmatter, and writes nothing.
- `mv <note> <folder>` prints the new path.
- Both append one line to `.pkm/moves.tsv`: `date<TAB>old<TAB>new`. A rename records names; a move records paths.
- Exit `0` on success, `1` when refused (a new name already taken, no single note with the old name, a day or close page, a folder that exists) or when a change could not be written. A refusal writes nothing. A failure part-way rolls every file back to its exact bytes, and says so on stderr.
- Usage errors (a new name with spaces, a folder outside the vault) exit `2`.

## Reading, posting and striking

- **`get <name>[#Section] [--lines a-b]`** prints the note, or one section, between `<<<note <path> lines a-b` and `>>>end`. The name resolves as `path` does, and may be a link such as `[[apollo#Decisions]]`. A section is the text of a heading (any level, any case) up to the next heading of the same or a higher level, without its trailing blank lines. `--lines` takes the note's own line numbers and narrows what is printed. Exit `1` when the note, section or lines are missing, `2` for a malformed range. `--plain` prints the same lines as someone outside the vault reads them, with no header or footer: `[[a|b]]` as `b`, `[[a]]` (with a heading or not) as the title of the note it names, or `a` when it names none; without the source links ` ([[YYYY-MM-DD…]])` of the day pages, the markers and a 📅 date; trailing spaces trimmed. The frontmatter, the blank lines after it, and struck lines (`~~…~~` after the list mark and box) are left out. Lines inside a code fence are printed as they are.
- **`post <path:line[-line]> <note>[#Section]`** copies those lines, verbatim, into the section, with ` ([[<page>]])` after the last one, where `<page>` is the source page's name (a shared vault's page keeps its writer, as `[[2026-11-12-sam]]`). The lines go right after the section's last line, with no blank between list items. An empty section, or a note that ends after its heading, gets a blank line first. A missing section is created at the end as `## <Section>`. It prints `path:line` of the first posted line. Exit `1` (nothing written) when the range contains a heading, when it contains an open task `- [ ]` (the task would show twice in `tasks`) or an event (it would show twice in `upcoming`), when the target is a day or close page, when the target is missing, or when the entry is already in the note anywhere (it prints that `path:line` and writes nothing). Exit `2` for a malformed source, a source outside the vault, or lines out of range.
- **`done <words | path:line> --next <day>`** marks a routine done and sets its next due date to `<day>` (`YYYY-MM-DD`, `today`, `tomorrow`, `+3d`, `+2w` or a weekday, from today), in place of its interval or cycle: done early or late, it moves on from there. An undated routine gets the `(due …)` before its `(every …)`. Exit `1` for a task that is not a routine; `2` for a day that can't be read, a missing day, or `--next` with `--drop`.
- **`moved <path:line> <when>`** is for an open task or an event whose date changed. It strikes the line, as `strike` does, and writes it again with the new date: in its `(at …)` or `(@ …)` when it has one, else in its `(due …)` or 📅 date, or as a new `(due …)` at its end. `<when>` is read from today. For an `(at …)` it is a value of [format.md](format.md), Events; a date alone keeps the old time, or the old length of a `to` range. For a `(due …)` it is a day. In a note, and on today's page, the new line goes right below the old one, with its indent and line end. From another day's page it goes on today's page, a task at the end of `## Tasks` and an event at the end of `## Log` as `- HH:MM` with the time now, and it puts ` ([[<the old page>]])` before its markers, in place of a day link already there. It prints `path:line: text` of the new line. Exit `1` (nothing written) for a line that is not an open task or an event, a line on a close page, and an event that comes back (add `(skip <date>)` and write that time as an event of its own); `2` for a malformed argument, a missing `<when>`, a when that can't be read, or a time for a task without an `(at …)`.
- **`strike <path:line>`** wraps the line's text, after its indent, list marker and task box, in `~~`, and adds ` ([[<today's page>]])`. Today's page is made when it is missing, so the link is never dead. It prints `path:line`. Exit `1` (nothing written) for a blank line, a heading, or a line that is struck already; `2` for a malformed argument.
- **`links --external [note]`** prints `path:line: address` for each `http(s)` address outside code, bare, or as a Markdown link with the address in its parentheses, once per address on each line, in the order of the listings. Without `--external` it exits `2` with one line that points to `pkm backlinks`.
- **`evidence [--verify] <note | ->`** checks the list items of a note's `## Now` section, or a close page whole, or stdin (`-`, reported as `-:N:`). A leading `> ` is taken off first, and struck items are skipped. A source is a link to a day page or to a note of `type: source`, a `path:line` naming a vault file, or an `http(s)` address. A link to any other note only says what the line is about. Findings print as `path:line: text` and exit `1`. `--verify` also reports each link that doesn't resolve, and each `path:line` whose file is missing or shorter than the line, and such a line is then not a source. Exit `2` without a note or `-`; exit `1` for a missing note or one without `## Now`.
- **`overview [--json]`** shows each note under the one its `part_of` names, which resolves as a link does. Sections, each only when it has lines, in this order: `== areas` (trees whose top note is `type: area`), `== projects` (`project` or `writing`), `== resources` (`course`, `topic` or `source`), `== other` (a top note of another type with notes under it), and `== archive` (`N notes in archive/`). A top note whose status is `done`, `dropped`, `published`, `sold`, `gone` or `archived` is left out, with its tree; an area never is. Day and close pages and the archive are not in the trees. A note whose parent is missing, archived or itself is a top note; notes in a circle are left out (`check` reports it). Tops come by name, and each note's children by name under it. A line is `path:<title line>: <titles from the top, joined by " / "> (<type>[, <status>])`. `--json` gives each note `kind` (`area`, `project`, `resource` or `other`), `path`, `line`, `text`, `type`, `status` (or `null`), `parent` (its path, or `null`) and `depth` (0 at the top), and the archive `{"kind": "archive", "path": null, "line": null, "text": ..., "count": N}`. Exit `1` when there is nothing to show.
- **`todo --every <rule> --in <note>`** writes the routine at the end of the note's `## Routines` section, made at the end of the note when it is missing, and prints `path:line`. The note resolves as a link does. Exit `1` for a note that doesn't exist or a day or close page; `2` for `--in` without `--every`.
- **`add --file <path> [text]`** copies the file to `files/<YYYY>/<MM>/<date>-<name>`, by the entry's day (`--day`, or today), where `<name>` is the slug of the file's name with its extension in lower case, and writes the entry `- HH:MM <text>: <link>`, or `- HH:MM <link>` with no text, where the link is a Markdown link with the name as its text and the file's path from the page's folder as its address. The file is copied, never moved. Exit `1`, writing nothing, when that place is taken; `2` for a file that can't be read, or with `-` or several lines of text.
- **`list --quiet <days>`** lists the notes the other filters match that no day page in the last `<days>` days links (the days are today and the days before it, by name, slug or alias). Day and close pages are never listed. Exit `2` when `<days>` is not a whole number.
- **`check --urls`** also GETs each distinct web address (curl, `--max-time 5`, following redirects, 8 at a time). An address that gives no answer is reported as `path:line: no answer: <url>` at each place it is used; a `404` or `410` as `path:line: <status>: <url>`. Other statuses count as answered, since private boards answer with a login page. It needs curl (exit `2` without it). A plain `check` never makes a request.

## Cycles, since and close

- **Cycles** are periods. The week is built in (`1w from monday`). A cycle of your own is set in `.pkm/config`: `cycle_<name>=<N>w from <weekday or date>` (a weekday only for `1w`), or `cycle_<name>=<N>m from <day 1-28 or date>`. A name is lowercase letters, digits and hyphens, not `week`, `last`, `today`, `yesterday`, nor all digits. Periods run both ways from the anchor. `close` names the cycle the close runs on (`week` by default).
- **`cycle [name] [--date D] [--json]`** prints `name<TAB>first<TAB>last` for the period holding the date (today by default), with a fourth field `close` on the close cycle. With no name it prints every cycle. `--json` gives `name`, `first`, `last` and `close` (`true` or `false`). Exit `1` for an unknown name.
- **`tags [--json]`** prints `count tag` for each tag, the most used first, then by name. `--json` gives `tag` and `count`.
- **`vaults [--json]`** prints `name<TAB>folder<TAB>ok|missing` for each `vault_<name>` of the user config, in its order. `--json` gives `name`, `path` and `state`.
- **Cycle routines**: an undated `(every <cycle>)` is due on the last day of the period holding today. `done` moves a dated one on from its due date: 7N days for an `Nw` cycle, and N months for an `Nm` cycle, on the same day of the month (or the month's last day when it is shorter). An undated one moves to the last day of the next period. It writes `(due D)` before the `(every …)` marker and keeps its box open. `check` reports a `(every <name>)` that names no cycle.
- **`upcoming [<days>] [--ics]`** lists today and the next `<days>` days (14) as `DATE KIND path:line: text`. The kinds: `overdue` and `due` (open tasks, routines included, and a task with an `(at …)` on the event's first day), `start` (the start date of a hidden task), `birthday` (every year, on its month and day), `target`, `deadline` and `warranty` (the frontmatter dates of a note that isn't closed), and `event`. An event is listed on each of its days in the window, so a several-day event that began before today is listed from today, and an event that comes back on each of its times but the skipped ones; a time that has passed today is still listed today. Events on close pages, in `archive/` and in closed notes are left out, as in [format.md](format.md), Events. The lines come by date; within a day, by kind name, the events among them by their start time with the whole-day ones first, then by path and line. The time is in the text, as written. With none, it prints nothing and exits `0`. `--json` gives each line `date`, `kind`, `path`, `line` and `text`, and `time` and `end` (`HH:MM`, or `null` for a whole-day event and for any other kind); with `--ics` it exits `2`.
- **`upcoming --ics`** prints an iCalendar file (RFC 5545) instead: one `VEVENT` for each event, each open task with an `(at …)`, and each birthday, from all of the vault, not only the window. An event that comes back is one `VEVENT` with `RRULE` (`FREQ`, `INTERVAL`, `UNTIL`) and an `EXDATE` for each skip; a birthday repeats yearly. A monthly or yearly one on a day some months lack (the 29th to the 31st, or 29 February) adds `RSCALE=GREGORIAN` and `SKIP=BACKWARD` (RFC 7529), so it falls on the last day of a shorter month, as in `upcoming`. Times are floating local times, with no time zone, `UNTIL` included; a whole-day event is a `DATE`, and a night shift ends on the next day. `SUMMARY` is the line's text without the list mark, the entry's time and the markers, with each link as its shown text, or the title of the note it names; a birthday's is `Birthday: <title>`, from the year in its date, or from this year when it has none. `UID` is made from the path and the summary, so it stays the same when lines above it move; a second line with the same summary in the same file adds `-2`, and so on. A vault with none prints a calendar with no events. `<days>` doesn't apply.
- **`since [last | YYYY-MM-DD | N | cycle] [--about NAME] [--under <note>] [--sum] [--limit n] [--json]`** covers the day pages of every writer from the start to today. `last` starts on the date in `.pkm/state` (set by `since --seen`, which stores the date and the time it ran), or the last 7 days. On that date, `last` leaves out the entries timed at or before the stored time; untimed lines on that day stay, and a state with only a date (the older form) starts on that date in full. `since --seen` prints `The next since last starts after <date> <time>.`; `N` is today and the `N-1` days before; a cycle is the period holding yesterday. Sections, each only when it has lines: `== notes` (`path:<title line>: # Title` for notes created in the range), `== log` (`path:line: text` for every line of those day pages, struck ones too, except the title and the `## Tasks` and `## Log` headings), `== tasks` (`path:line: overdue: text` and `path:line: waiting N days: text` for every open task, in path order), `== marked` (`path:line: text` for `! `, `Decided:`, `Idea:` and `?`-ending entries, struck ones left out), `== names` (`name  N mentions  last <today|yesterday|N days ago>`, by count then name). `--about NAME` keeps the lines that link NAME, a line under a `###` heading included when the heading links it (until the next heading of level 1, 2 or 3), and leaves out `== notes`; NAME is a note's name, slug, alias, `[[link]]` or path, or a name with no note yet. `--under <note>` keeps the lines about the note's tree, as below, and the notes of the tree in `== notes`; with `--about`, a line must be kept by both. `--sum` prints, in place of the sections, the lines of `== log` that say how long something took ([format.md](format.md), Tasks 6), as `path:line: <duration>: text`, then `Total: <duration> in N lines`; a duration is written `40m`, `1h` or `1h30`. `--limit` applies to the lines, and the total counts them all. With none, it prints `Nothing timed since <date>.` and exits `1`. With `--json` each line is `kind` `time` with its `minutes`, and the last is `{"kind": "total", "path": null, "line": null, "text": null, "minutes": N}`. `--limit` applies per section, with the footer on stderr. With no line in any section, it prints `Nothing since <date>.` and exits `1`. `--json` gives `kind` (note, log, task, marked, name), with `state` and `days` for a task, and `name`, `count` and `last` (ISO) for a name. `since --seen` writes today's date to `.pkm/state` and prints where the next `since last` starts; with any other argument it exits `2`.
- **`close [--cycle name] [--date D] [--quarter] [--json]`** closes the period holding yesterday (or the one holding `--date`). Its first line: `== <cycle> <first> to <last>: <n> entries (closes/<year>/<first>-<cycle>.md)`, where the entries are the log lines of the period's day pages. Then only the sections with lines: `== tasks` (overdue tasks, and tasks on a day page 21 days old or more as `open N days:`), `== open` (the period's questions as `question:`, and every waiting task), `== for` (every open task and the period's questions with a `(for …)`, which `== tasks` and `== open` then leave out, as `path:line: for <who>[, overdue | , waiting N days | , waiting | , due D | , question]: text`, by who, then path and line; `<who>` is the writer's name with a capital, or the title of the note linked; `--json` gives them `kind` `for` and `name` the who), `== due` (from today to the end of the next period, in the lines `upcoming` prints, without the overdue ones), `== marked` (the period's `!`, `Decided:` and `Idea:` entries), `== names` (`name  N mentions, no note` for a link to no note on three lines or more of day pages), `== quiet` (`path:<title line>: last linked <date>: # Title` for projects not done and people linked 15 to 42 days ago and not in the last 14 days), and `== ideas` (every `Idea:` entry and someday task; in a period holding the first day of January, April, July or October, or with `--quarter`). Exit `0`.
- **`new close [--cycle name] [--date D]`** writes the close page of the period, at `closes/<year>/<first day>-<cycle>.md`, titled `<Cycle> of <first day>`. It takes no title (exit `2`), and an existing page exits `1` with its path.

## Recall

- **`recall [note] [--json] [--limit n]`** lists the questions due today or earlier as `path:line: text`, oldest date first, then path and line. A question is an entry that ends with `(recall YYYY-MM-DD <N>d)`, outside code; a struck line never comes up. With a note name, only that note's questions. With none due, it exits `1` with one line on stderr: when the next is due, or that there are no questions.
- **`recall <path:line> yes|no`** rewrites only the mark. `yes` moves the interval to the next rung of 1, 3, 7, 14, 30, 60 and 120 days above the current one (120 stays 120); `no` sets it to `1d`. The next date is today plus the new interval. It keeps the file's line ends and prints the rewritten line as `path:line: text`. A line with no mark exits `1`.
- **`recall add <note> <question> [--answer <text>]...`** writes `- <question> (recall <tomorrow> 1d)` at the end of the note's `## Questions` section, creating the section at the end of the note when it is missing. Each `--answer` is an indented `  - <text>` line below the question. It keeps the file's line ends and prints `path:line` of the question. It exits `1`, and writes nothing, for a day or close page, a question the note already has (printing that `path:line`), or a note that doesn't exist. A missing question or note name exits `2`.
- **`check`** flags a malformed mark (a date that isn't `YYYY-MM-DD`, an interval without `d`, a mark that doesn't end the line), and a mark inside a task box. Recall lines never show in `tasks`, `since`, `close` or `upcoming`.
